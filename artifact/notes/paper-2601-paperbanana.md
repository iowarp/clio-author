## 2. Problem Statement and Motivation (Sec 1 Introduction)

- Autonomous AI scientists (LLM-powered) automate literature review, idea generation, experiment iteration, but "scientific discoveries achieve their full value only through effective communication." Current AI scientists "struggle to visually communicate discoveries, especially for generating illustrations (diagrams and plots) that adhere to the rigorous standards of academic manuscripts."
- **Methodology diagrams** are the hardest illustration task — demanding both content fidelity and visual aesthetics.
- Prior work uses the **code-based paradigm**: TikZ (Belouadi & Eger 2024; Belouadi et al. 2025), Python-PPTX (Zheng et al. 2025), or SVG to programmatically synthesize diagrams. "While effective for structured content, these methods can encounter expressiveness limitations when attempting to produce the intricate visual elements – such as specialized icons and custom shapes."
- Conversely, image generation models (Deepmind 2025; OpenAI 2025a; Team et al. 2025; Wu et al. 2025a) have strong instruction-following but "consistently generating academic illustrations that meet scholarly standards remains a difficult task."
- Manual figure crafting is "a significant bottleneck in the effective visual communication of scientific discoveries."
- **Input to PaperBanana:** a methodology description + diagram caption. It orchestrates VLMs and image-gen models (e.g., **Gemini-3-Pro** and **Nano-Banana-Pro**) to retrieve reference examples, devise content+style plans, render images, iteratively refine via self-critique. This "reference-driven collaborative workflow" masters logical composition and stylistic norms.
- **Contributions (3):** (1) propose PaperBanana fully-automated agentic framework; (2) construct PaperBananaBench; (3) comprehensive experiments outperforming baselines.
- Figures marked with the banana icon in the manuscript were entirely generated by PaperBanana.

## 3. Task Formulation (Sec 2)

Formalized as learning a mapping from **source context** S (essential information) and **communicative intent** C (scope/focus of desired illustration) to a visual representation:

- **Eq (1):** `I = f(S, C)` — generate image I that faithfully visualizes S while fulfilling intent C.
- Optionally augmented by N **reference examples** E = {E_n}, each a triplet `E_n = (S_n, C_n, I_n)` (context, intent, reference illustration).
- **Eq (2):** `I = f(S, C, E)`, where E defaults to ∅ for zero-shot generation.
- Focus: **methodology diagrams**. Here S = textual method description (e.g., methodology sections), C = figure caption specifying scope/focus (e.g., "Overview of our framework").

## 4. Methodology (Sec 3) — The Agents and Two-Phase Pipeline

PaperBanana is a **reference-driven agentic framework** orchestrating a collaborative team of **FIVE specialized agents: Retriever, Planner, Stylist, Visualizer, and Critic** (prompts in Appendix G). Two phases (Figure 2):
- **Linear Planning Phase:** retrieve relevant reference examples and synthesize a stylistically optimized description.
- **Iterative Refinement Loop:** Visualizer + Critic transform description into visual output over multiple rounds.

### Inputs and overall flow (from Figure 2)
INPUTS: Source Context (S) + Communicative Intent (C) → [LINEAR PLANNING PHASE] Retriever Agent → Relevant Examples (E) → Planner Agent → Initial Description (P) → Stylist Agent → Optimized Description (P*) → [ITERATIVE REFINEMENT LOOP] Visualizer Agent → Generated Image (I_t) → Critic Agent → Refined Description (P_{t+1}), looping **T = 3 rounds** → FINAL OUTPUT: Final Illustration (I_T). A **Reference Set (R)** feeds Retriever; **Aesthetic Guidelines (G)** feed Stylist; **Factual Verification** loops back from Critic.

### Retriever Agent
- Given S and C, identifies N most relevant examples E = {E_n} ⊂ R from the **fixed reference set R**. Each E_i ∈ R is a triplet (S_i, C_i, I_i).
- Uses a **generative retrieval** approach: the VLM performs selection over candidate metadata.
- **Eq (3):** `E = VLM_Ret(S, C, {(S_i, C_i)}_{E_i ∈ R})`.
- The VLM is "instructed to rank candidates by matching both research domain (e.g., Agent & Reasoning) and diagram type (e.g., pipeline, architecture), with **visual structure being prioritized over topic similarity**." Provides a concrete foundation for structural logic and visual style.

### Planner Agent ("cognitive core")
- Takes S, C, and retrieved E. By **in-context learning** from demonstrations in E, translates unstructured/structured data in S into a comprehensive detailed textual description P of the target illustration.
- **Eq (4):** `P = VLM_plan(S, C, {(S_i, C_i, I_i)}_{E_i ∈ E})`.

### Stylist Agent ("design consultant")
- Addresses the problem that "academic style" definitions are often incomplete. The Stylist **traverses the entire reference collection R to automatically synthesize an Aesthetic Guideline G** covering key dimensions: color palette, shapes and containers, lines and arrows, layout and composition, typography and icons (Appendix F for summarized guideline + implementation).
- Refines initial description P into stylistically optimized P*:
- **Eq (5):** `P* = VLM_style(P, G)`.

### Visualizer Agent
- Receives P*; collaborates with Critic to render and refine. Uses an image generation model. At iteration t, given description P_t:
- **Eq (6):** `I_t = Image-Gen(P_t)`, with initial description P_0 set to P*.

### Critic Agent (closed-loop refinement)
- Inspects generated image I_t against original source context (S, C) to identify "factual misalignments, visual glitches, or areas for improvement." Provides targeted feedback and produces refined description P_{t+1}:
- **Eq (7):** `P_{t+1} = VLM_critic(I_t, S, C, P_t)`.
- This loop **iterates for T = 3 rounds**, final output I = I_T. Ensures the final illustration meets academic standards.

### Extension to Statistical Plots (Sec 3, end)
- Adjusts Visualizer and Critic. For numerical precision, the Visualizer converts P_t into **executable Python Matplotlib code**: `I_t = VLM_code(P_t)`. Critic evaluates rendered plot and refines: `P_{t+1} = VLM_critic(I_t, S, C, P_t)`. Same T = 3 round process.
- They "prioritize this code-based approach for accuracy" but also explore direct image generation in Sec 6. Adjusted prompts in Appendix G.2.

This is the most directly relevant part for clio-parser:

Subsequently, we utilize the **MinerU toolkit (Niu et al., 2025)** to parse these documents, **extracting the text of the methodology sections, and all the diagrams and their captions** in the paper."

- Average **source context length = 3,020.1 words**, average **figure caption = 70.4 words** (Figure 3 caption).

## 6. Benchmark — PaperBananaBench (Sec 4)

Curated from NeurIPS 2025 methodology diagrams. Construction pipeline:

### 4.1 Data Curation
1. **Collection & Parsing:** 2,000 papers sampled from 5,275 NeurIPS 2025 publications; PDFs parsed with MinerU.
2. **Filtering:**
   - Discard papers without methodology diagrams → **1,359 valid candidates**.
   - Restrict aspect ratio (w:h) to **[1.5, 2.5]**. Below 1.5 excluded (methodology diagrams need wider landscape layouts); above 2.5 unsupported by current image gen models. Outliers would "introduce bias in side-by-side evaluations by revealing the human origin of candidates." → **610 valid candidates**, each a tuple (S, I, C).
3. **Categorization:** Four classes by visual topology and content: **Agent & Reasoning, Vision & Perception, Generative & Learning, Science & Applications** (definitions in Appendix C). **Gemini-3-Pro** does categorization (hybrid elements → predominant category).
4. **Human Curation:** Annotators verify/correct extracted descriptions + captions, validate categorizations, filter out diagrams of insufficient visual quality (overly simplistic, cluttered, abstract). → **584 valid samples**.
- **Partition:** randomly split into two equal subsets — **test set (N = 292)** for evaluation and **reference set (N = 292)** for retrieval-augmented in-context learning.
- **Category distribution (Figure 3 donut):** Agent & Reasoning 31.5%, Vision & Perception 25.0%, Generative & Learning 25.0%, Science & Application 18.5%.
- **Width-Height ratio distribution:** [1.5,2) = 59.5%, [2,2.5] = 40.5%.

### 4.2 Evaluation Protocol
- **VLM-as-a-Judge**, referenced comparison: judge compares model-generated diagram against human-drawn diagram, decides which better satisfies each criterion. Inspired by Quispel et al. (2018).
- **Four evaluation dimensions** on two perspectives:
  - **Content:** *Faithfulness* (alignment with source context + intent) and *Conciseness* (focus on core info without visual clutter).
  - **Presentation:** *Readability* (intelligible layouts, legible text, no excessive crossing lines) and *Aesthetics* (adherence to stylistic norms of academic manuscripts).
- **Referenced Scoring:** For each dimension, judge outputs **Model wins / Human wins / Tie** → mapped to scores **100, 0, 50** respectively.
- **Hierarchical aggregation** (principle "show the truth," Mackinlay 1986; Quispel 2018; Tufte & Graves-Morris 1983): faithfulness and readability are **primary** dimensions; conciseness and aesthetics are **secondary**. Primary decides overall winner if decisive; ties broken by secondary. Ensures content fidelity and clarity take precedence over aesthetics and conciseness.

## 7. Experiments and Results (Sec 5)

### 5.1 Baselines and Models
Three baseline settings:
1. **Vanilla** — directly prompt image gen model with context + caption.
2. **Few-shot** — vanilla + 10 few-shot examples (triplets: description, caption, diagram) for in-context learning.
3. **Paper2Any** (Liu et al., 2025) — agentic framework generating diagrams to present high-level ideas; "closest to our setting."
- VLM backbone default: **Gemini-3-Pro**. Image gen models tested: **Nano-Banana-Pro** and **GPT-Image-1.5**.

### 5.2 Evaluation Settings
- VLM Judge: **Gemini-3-Pro**. Validated on 50 sampled cases (25 vanilla, 25 ours), two-fold validation.
- **Inter-Model Agreement (Consistency):** Kendall's tau with **Gemini-3-Flash** across 4 dims + aggregation = **0.51, 0.60, 0.45, 0.56, 0.55**; with **GPT-5** = **0.43, 0.47, 0.44, 0.42, 0.45**. (tau > 0.4 = relatively strong agreement.)
- **Human Alignment (Validity):** Kendall's tau between Gemini-3-Pro and human annotations = **0.43, 0.57, 0.45, 0.41, 0.45**.

### 5.3 Main Results (Table 1) — scores out of 100; Human reference fixed at 50 each

|---|---|---|---|---|---|
| **Vanilla settings** | | | | | |
| GPT-Image-1.5 | 4.5 | 37.5 | 30.0 | 37.0 | 11.5 |
| Nano-Banana-Pro | 43.0 | 43.5 | 38.5 | 65.5 | 43.2 |

- Best PaperBanana (w/ Nano-Banana-Pro) beats vanilla Nano-Banana-Pro on every metric and wins Conciseness/Readability/Aesthetic/Overall outright. Improvements over Vanilla Nano-Banana-Pro baseline (stated in text/abstract): **Faithfulness +2.8%, Conciseness +37.2%, Readability +12.9%, Aesthetics +6.6%, Overall +17.0%.**
- GPT-Image poor due to weaker instruction-following and text rendering vs Nano-Banana-Pro.
- Paper2Any underperforms because it "prioritizes the presentation of high-level ideas rather than the faithful depiction of specific methodological flows" (objective mismatch).
- **Per-category overall scores:** Agent & Reasoning highest (**69.9%**), then Scientific & Application (58.8%), Generative & Learning (57.0%), Vision & Perception lowest (**52.1%**).
- **Blind human evaluation** (50 cases, vs vanilla Nano-Banana-Pro, 3 human judges): average **win / tie / loss = 72.7% / 20.7% / 6.6%**.
- Caveat: PaperBanana still **underperforms human reference in faithfulness** (45.8 vs 50). Failure analysis in Appendix Figure 10.

Findings:
- **Retriever** (rows ④–⑥): without reference examples (no-retriever), significantly worse on Conciseness, Readability, Aesthetics (Planner defaults to verbose, exhaustive descriptions; lacks exposure to academic aesthetics). ### 5.5 PaperBanana for Statistical Plots
- Methodology diagrams prioritize aesthetics/logic; statistical plots demand numerical precision → standard image gen models unsuitable → uses **executable code**.
- **Testset Curation:** repurpose **ChartMimic (Yang et al., 2025b)** (chart-to-code dataset, plots from arXiv + Matplotlib galleries paired with human-curated Python code). Use Gemini-3-Pro to extract tabular data from code + synthesize brief description. → **240 test cases, 240 reference examples**, stratified across **seven plot categories** (bar, line, tree & pie, scatter, heatmap, radar, miscellaneous) and **two complexity levels (easy/hard)**. Appendix D for filtering.
- **Figure 4 results (vs vanilla Gemini-3-Pro):** gains **Faithfulness +1.4%, Conciseness +5.0%, Readability +3.1%, Aesthetics +4.0%, Overall +4.1%.** "PaperBanana slightly surpasses human performance in Conciseness, Readability, and Aesthetics while remaining competitive in Faithfulness."

## 8. Discussion (Sec 6)

### 6.1 Enhancing Aesthetics of Human-Drawn Diagrams
- Can aesthetic guidelines G elevate existing human-drawn diagrams? Pipeline: Gemini-3-Pro formulates up to **10 actionable suggestions** based on the original diagram and G → executed by Nano-Banana-Pro to refine.
- Across 292 test cases, refined diagrams achieved **win / tie / loss = 56.2% / 6.8% / 37.0%** in aesthetics vs original human-authored counterparts. Example Figure 6 (original from Kim et al. 2025).

### 6.2 Coding vs Image Generation for Statistical Plots (Figure 5)
- Compare code-based (Gemini-3-Pro) vs image-gen-based (Nano-Banana-Pro) Visualizer.
- **Trade-off:** image generation excels in presentation (Readability, Aesthetics) but underperforms in content fidelity (Faithfulness, Conciseness). Image models faithfully render sparse plots but "struggle with dense or complex data, exhibiting numerical hallucinations or element repetition" (Appendix Figure 9).
- Win rates from Figure 5 (Code vs IMG, dashed Human=50): Faithfulness 45.4 vs 39.6; Conciseness 62.3 vs 55.0; Readability 51.3 vs 57.1; Aesthetic 54.4 vs 62.4; Overall 56.0 vs 56.8.
- Conclusion: **hybrid** — image gen for sparse visualizations, code for dense plots, may offer best balance.

## 9. Related Work (Sec 7)

- **7.1 Automated Academic Diagram Generation:** code-based (TikZ, Python-PPT) limited expressiveness. Image gen models a promising alternative. Concurrent work: **AutoFigure (Zhu et al. 2026)** and **AutoFigure-Edit (Lin et al. 2026)** transform scientific content into symbolic representations before rendering as images using GPT-Image. PaperBanana claims broader generalizability via adaptive retrieval + academic-style transfer, unifying methodology diagrams and statistical plots. Closest benchmark: **SridBench (Chang et al. 2025)**.
- **7.2 Coding-Based Data Visualization:** lineage from LIDA, Data2Vis (LSTM→Vega-Lite), few/zero-shot coding (Dibia 2023; Galimzyanov 2025; Li 2024; Tian 2024), agentic frameworks (Chen 2025 CoDA; Goswami 2025 PlotGen; Seo 2025; Yang 2024 MatPlotAgent) using test-time scaling and self-reflection. Plot-to-code reversal (Wu 2025b Plot2Code; Yang 2025b ChartMimic).

## 11. Limitations and Future Work (Sec 9)
- **Towards Editable Academic Illustrations:** "The most prominent limitation lies in the **raster nature of its output**." Vector graphics preferred for scalability/edit; raster hard to edit. 4K-resolution generation is a workaround but doesn't solve post-generation editing. Three solutions envisioned: (1) image editing models (Nano-Banana-Pro) for minor adjustments; (2) reconstruction pipeline (Paper2Any, Edit Banana, AutoFigure-Edit) using **OCR for text extraction + SAM3 for pattern segmentation**, reassembled on slides (Python-PPTX); (3) GUI Agent operating vector design software (Adobe Illustrator).
- **Trade-off between Style Standardization and Diversity:** unified style guide ensures rigid compliance but reduces stylistic diversity; future work = dynamic style adaptation.
- **Challenge of Fine-Grained Faithfulness:** gap vs human in faithfulness; most prevalent errors involve **fine-grained connectivity** (misaligned start/end points, incorrect arrow directions) that escape current critic models; hinges on advancing fine-grained visual perception of foundation VLMs.
- **Advancing Evaluation Paradigms:** VLM-as-a-Judge has limits; quantifying structural correctness hard; future = fine-grained structure-based (Liang & You 2025 DiagramEval) or rubric-based metrics; training custom reward models to align subjective dims.
- **Test-Time Scaling for Diverse Preferences:** currently single output per query; extension = generate spectrum of candidates → generate-and-select workflow with VLM-based preference models.
- **Extension to Broader Domains:** generalizable paradigm — "retrieval to instruct the model on *what* to generate... and automatic style summarization to teach it *how* to generate." Decouples structural planning from aesthetic rendering, bypassing domain-specific fine-tuning. Promise for UI/UX design, patent drafting, industrial schematics.

## 12. Memory, Context Injection, and Grounding (cross-cutting)

- **Grounding / Factual Verification:** The Critic Agent grounds each generated image against the original (S, C) every round (Eq 7), producing a corrective refined description — Figure 2 labels this the "Factual Verification" feedback loop. This is the core grounding mechanism.
- **Context injection via retrieval (in-context learning):** Retriever injects N reference triplets (S_i, C_i, I_i) into the Planner's prompt (Eq 4). Notably the **reference illustrations I_i (images) are injected**, not just text — multimodal in-context examples. Ablation shows the *presence* of structural/stylistic exemplars matters more than precise content matching (random retriever ≈ semantic retriever).
- **Style-guide synthesis as distilled memory:** Stylist traverses the entire reference set R once to synthesize a reusable Aesthetic Guideline G (color palette, shapes/containers, lines/arrows, layout/composition, typography/icons), then injects G into every description refinement (Eq 5). G is essentially a compressed, reusable "style memory" derived from the corpus.
- **No persistent learned memory / no fine-tuning:** the system is entirely prompt-driven (training-free); all "memory" is the fixed reference set R plus the synthesized G. The paper explicitly frames the paradigm as avoiding "expensive domain-specific fine-tuning."

## Implications for clio-parser

1. **MinerU is the parsing backbone here too.** PaperBanana uses MinerU 2.5 (arXiv:2509.22186) to convert NeurIPS PDFs into (methodology-section text, diagram images, captions). For clio-parser, this validates a PDF→structured-content pipeline where MinerU extracts (a) section text, (b) figure images, and (c) figure captions — exactly the "PDF→Markdown + figures" decomposition. Worth checking how clio-parser's parser compares to MinerU's section/figure/caption extraction quality.
2. **The (S, I, C) triplet is a clean, reusable extraction schema:** source context (section text), illustration (figure image), communicative intent (caption). clio-parser could emit this triplet per figure as a first-class output — it is directly consumable by downstream retrieval/generation systems.
3. **Caption ↔ figure ↔ section-text linkage matters.** Their curation depended on correctly associating each diagram with both its caption and the relevant methodology text. A parser that reliably links figures to captions and to the surrounding/method section text (not just dumping images) is more valuable. Human curation was still needed to fix mis-extracted descriptions/captions and filter low-quality figures — i.e., extraction is noisy and benefits from validation passes.
4. **Filtering heuristics for figure quality:** aspect-ratio filtering (w:h in [1.5, 2.5]) and discarding overly simplistic/cluttered/abstract diagrams. If clio-parser surfaces figure metadata (dimensions, type/category), it eases downstream dataset construction.
5. **Figure categorization is automatable** (Gemini-3-Pro into 4 topology/content classes). clio-parser could optionally tag extracted figures with a diagram-type label.
6. **Average sizes for budgeting:** method-section context ~3,020 words; captions ~70 words — useful for chunking/context-window planning if clio outputs feed an LLM.
7. **Grounding loop pattern:** the Critic's "Factual Verification" against (S, C) is a reusable QA pattern — if clio-parser produces structured extractions, a verify-against-source loop can catch hallucinated/dropped content.
8. **Retrieval over a fixed corpus + synthesized style guide** is a lightweight, training-free augmentation pattern that clio-parser-style extracted corpora could feed directly (each parsed paper becomes a retrievable (S, C, I) exemplar).

## 10-Line Summary

1. PaperBanana (Google Cloud AI Research + Peking U., arXiv:2601.23265, Mar 2026) automates publication-ready academic illustrations for AI scientists.
2. It is a training-free agentic framework with FIVE agents: Retriever, Planner, Stylist, Visualizer, Critic, powered by Gemini-3-Pro + Nano-Banana-Pro/GPT-Image-1.5.
3. Two phases: a Linear Planning Phase (retrieve refs → plan content → stylize) and an Iterative Refinement Loop (Visualizer↔Critic, T=3 rounds with factual verification).
4. Task = map source context S + communicative intent (caption) C to image I, optionally with reference triplets E=(S_i,C_i,I_i): I=f(S,C,E).
5. Content is extracted from NeurIPS 2025 PDFs using the MinerU toolkit (methodology text + diagrams + captions), forming (S,I,C) triplets.
6. PaperBananaBench: 2000→1359→610→584 samples after filtering/curation, split into 292 test + 292 reference, in 4 categories; evaluated via VLM-as-a-Judge on faithfulness, conciseness, readability, aesthetics.
7. Best variant (w/ Nano-Banana-Pro) scores 45.8/80.7/51.4/72.1, Overall 60.2, beating vanilla Nano-Banana-Pro (+17.0% overall) and Paper2Any (8.5); blind human win/tie/loss = 72.7/20.7/6.6%.
8. Ablations: Critic + 3 iterations recover faithfulness; Stylist boosts aesthetics but can drop faithfulness; random retriever ≈ semantic retriever (structure > content match).
9. Extends to statistical plots via Matplotlib code generation (beats vanilla Gemini-3-Pro +4.1% overall); code best for dense data, image-gen best for sparse plots.
10. Limitations: raster (non-editable) output, fine-grained connectivity faithfulness errors, style-vs-diversity trade-off, and VLM-judge limitations; future = editable/vector output, structure-based metrics, test-time scaling.
